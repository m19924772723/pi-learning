## 一、章节核心要点（问题→机制）

1. **「统一模型调用」→ pi-ai 单一抽象**：不同 LLM（OpenAI/Anthropic/Bedrock…）消息格式与调用方式各异，pi-ai 用一套 `Message`/`Model`/`Tool` 原子类型 + 统一流式入口 `streamSimple` 抹平差异，其余层不直接碰厂商 SDK。
2. **「Agent 反复思考-行动」→ pi-agent-core 循环**：自身不关心业务，只维护 `AgentState`、`agentLoop`、`AgentEvent`、`Session/compact`，抽象掉 Agent 最难的状态与循环。
3. **「具体业务」→ pi-coding-agent**：最厚一层，实现 read/bash/edit/write 等工具、扩展系统、CLI、会话持久化，`cli.ts` 为入口。
4. **分层规则 = 依赖方向单向向上**：顶层可直接依赖底层（coding-agent 直接依赖 pi-ai 拿 `ImageContent` 原子类型），底层绝不 import 上层，保证可独立替换。
5. **类型「原子→分子→材料」递进**：`pi-ai.Tool`（LLM 只知长什么样）→ `agent-core.AgentTool extends Tool`（加 execute/executionMode）→ `core.ToolDefinition`（再加渲染/扩展 ctx，独立 interface 结构兼容而非继承），底层类型从不被修改。
6. **分层非教条**：可只用 pi-ai（纯调 LLM）、pi-ai+agent-core（自定义 Agent）、三层全用；唯一硬约束是底层不得 import 上层（用"去掉上层能否运行"验证）。
7. **ui 层完全独立**：pi-tui 运行时只依赖 `marked` + `get-east-asian-width`，不含任何 AI/pi 包，作为显示工具被 coding-agent 调用。

## 三、验证的关键结论

1. **依赖方向单向向上整体成立**：coding-agent/package.json:51-70 列 @pi-ai/@pi-core/@pi-tui；agent/package.json:57-64 只向上依赖 pi-ai；ai/package.json:66-77 无任何 agent/coding-agent。
2. **类型递进扩展完全吻合**：ai/src/types.ts:470 `Message=User|Assistant|ToolResult`；agent/types.ts:387 `AgentTool` 用 `extends` 扩展并加 `executionMode`；extensions/types.ts:451 `ToolDefinition` 为独立 interface，execute 签名比 AgentTool 多了 ctx。
3. **跨层引用是使用通用原子而非破坏依赖**：`ImageContent` 等定义仍在 pi-ai 一处统一定义（ai/types.ts），原子唯一来源。
4. **入口链路与教程一致**：coding-agent/cli.ts:1-6 含 `#!/usr/bin/env node` + `main(process.argv.slice(...))`，仅多调用一次 `setupCli()`。
5. **pi-ai 分层自证**：`index.ts` 明确 "Core only… no compat"，厂商 factory/api 全部子路径导出（`./providers/*`、`./api/*`、`./compat`），实现"统一外壳 + 独立提供商 + 独立 registry"。

## 四、矛盾 / 漂移 / 疑问

- ① **包架构大幅扩容**：教程"五个包"已过时。本地 0.85.1 实际有 chord/tui/telemetry/ai/agent/protocol/client/server/evals/coding-agent 约 10 个核心包 + 5 个 `staged-backends*`；教程 2.5 的实验编排包（orchestrator）已不在仓库。
- ② **"pi-ai 不依赖任何 pi 包"不成立**：ai/package.json:69 依赖 `@earendil-works/pi-telemetry`（同命名空间底层观测包）。"不依赖上层"仍成立，措辞应改"除自身观测包外不依赖 pi 包"。
- ③ **计数漂移**：KnownApi 教程 9、本地 **10**（ai/src/types.ts:17-27）；KnownProvider 教程 35、本地 **40**（:35-75，新增 radius/vercel-ai-gateway/qwen/xiaomi 系列）。
- ④ **行号整体右移**（Extension 1585→1765、ToolDefinition 435→451），二次开发以符号名定位。

## 五、一句话总结

三层分层（pi-ai→agent-core→coding-agent、依赖单向向上、类型 Tool→AgentTool→ToolDefinition 递进）在本地 0.85.1 完全成立；需打补丁：包数量"核心五包"→约 10 包、pi-ai 依赖 pi-telemetry、KnownApi/Provider 计数增长、orchestrator 包已移除。
