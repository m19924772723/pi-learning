## 一、两次架构图对比

### Day 1（初学时）理解：三层静态结构

```
┌──────────────────────────────┐
│  服务层：Express + SSE 桥接    │
├──────────────────────────────┤
│  Agent 层：createAgentSession │
│  （黑盒：prompt 进去，回复出来）│
├──────────────────────────────┤
│  模型层：models.json 多 Provider │
└──────────────────────────────┘
```

Day 1 的理解是**静态分层**：知道三层存在、请求从服务层流到模型层，但 Agent 层内部是黑盒，工具和事件都"知道有、说不清"。

### Day 20（学完后）理解：动态回路 + 两条主线

```
┌────────────────────────────────────────────────┐
│ 服务层  Express + SSE（res.on("close") 断开处理）│
└───────────────┬────────────────────────────────┘
                │ POST /chat → session.prompt(msg)
┌───────────────▼────────────────────────────────┐
│ Agent 层（agent-loop：模型 → 工具 → 消息 → 事件） │
│                                                │
│  【主线 1：事件驱动】                            │
│  pi.on("tool_call") 拦截危险 SQL（执行前拦截）    │
│  subscribe → tool_execution_start/end 事件日志  │
│  turn_end / agent_settled 轮次边界               │
│                                                │
│  【主线 2：安全纵深】                            │
│  人设兜底（系统提示：只读工具）→ 扩展层拦截        │
│  （正则模式：DROP/DELETE/分号/UNION…）→           │
│  解析层拒绝（SELECT 白名单子集 + 未知表/列）      │
└───────────────┬────────────────────────────────┘
                │ run_sql（只读 SELECT）
┌───────────────▼────────────────────────────────┐
│ 数据层  sales.csv（6 列白名单，中文列名）          │
└────────────────────────────────────────────────┘
```

**两次理解的差异（Day 20 新增的三点）：**
1. **Agent 层不是黑盒，是 Loop**：M03 学到的 agent-loop 五环节（模型调用 → 工具调用 → 消息整理 → 事件广播 → 下一轮），Day 1 只知道"会自己调用工具"，Day 20 知道每一轮由 `stopReason` 决定流转分支（max/done/length/toolUse）。
2. **事件不是"通知"，是可编程接口**：`pi.on` 不只用于观察，还能 `block` 工具调用——Day 19 的拦截就是事件驱动能力的实际收益。
3. **安全不是靠"模型自觉"**：真实链路测试证明模型自己就拒绝写危险 SQL（人设 + 工具描述兜底），但生产上不能只信这一层，所以做了扩展层正则拦截 + 解析层白名单的双保险。
