## 一、章节核心要点（问题→机制）

1. **两层消息**：LLM API 只认 3 种消息（user/assistant/toolResult），Agent 内部还有大量功能性数据（Bash 执行记录、压缩摘要、分支摘要）→ `Message`（3 种标准）与 `AgentMessage`（标准 + 自定义扩展）两层；自定义消息以结构化形式存进 `context.messages`（服务 UI/持久化），在调用 LLM 的边界才做有损翻译。
2. **声明合并扩展点**：核心包留空接口 `CustomAgentMessages`（"Empty by default"），应用用 TypeScript **声明合并**（`declare module`）注入自己的消息类型，编译器自动把新类型并入 `AgentMessage` 联合——核心包零依赖、应用层全栈类型安全。
3. **convertToLlm 翻译器**：按 `role` 分派的 switch，把 4 种自定义消息统一翻译成 `user` 角色消息（摘要类加 `<summary>` XML 标签），标准 3 种直接透传。
4. **两阶段管道**：先 `transformContext`（同层：AgentMessage[]→AgentMessage[]，可选），再 `convertToLlm`（跨层：AgentMessage[]→Message[]，必须），两者可独立替换；换 Provider 也无需动 convertToLlm（Provider 协议翻译在 pi-ai 层独立完成）。
5. **excludeFromContext 三种可见性**：`!!` 前缀命令要"UI 能看、LLM 不能看"→ 布尔字段在翻译时返回 `undefined` 被 filter 掉，数据仍在 `context.messages` 中——构成全可见 / LLM 不可见 / 仅持久化三级。

## 三、验证的关键结论

1. **LLM 标准消息确为封闭三成员**：`packages/ai/src/types.ts:470` `export type Message = UserMessage | AssistantMessage | ToolResultMessage;`；UserMessage content 为 `string | (TextContent | ImageContent)[]`（:424），AssistantMessage content 为 `(TextContent | ThinkingContent | ToolCall)[]` 且必含 api/provider/model/usage/stopReason（:430-440）。
2. **两层联合与空扩展点成立**：`packages/agent/src/types.ts:326` `AgentMessage = Message | CustomAgentMessages[keyof CustomAgentMessages]`，:317-319 接口注释即 "Empty by default - apps extend via declaration merging"。
3. **管道顺序先 transform 后 translate**：agent-loop.ts:288-293 先 `config.transformContext(messages, signal)`（类型不变），再 `config.convertToLlm(messages)`，产物填入 `llmContext.messages` 后交给 `streamFunction(config.model, llmContext, ...)`（:296-306）。
4. **一切自定义消息终成 user**：core/messages.ts:148-194 四个自定义 role 全部转 `{role:"user", content:[{type:"text",...}], timestamp}`；`bashExecution` 且 `excludeFromContext` 时 `return undefined`（:154-156），末尾 `.filter(m => m !== undefined)`（:194）实现过滤；`!!` 前缀→excludeFromContext 链路在 interactive-mode.ts:3107-3116（`text.startsWith("!!")`）与 agent-session.ts:3044-3067（recordBashResult 构造消息并 push 进 `agent.state.messages`）。
5. **声明合并注册了恰好 4 种自定义消息**：core/messages.ts:70-77 `declare module "@earendil-works/pi-agent-core"` 注入 bashExecution/custom/branchSummary/compactionSummary——3 标准 + 4 自定义 = 7 种。

## 四、矛盾 / 漂移 / 疑问

- **行号漂移实测**：ai/types.ts 消息区 +50~62；agent/types.ts +12；agent-loop.ts +13~18；coding-agent messages.ts 三处零漂移。
- **小疑问**：核心包声明合并的文档注释示例用 `declare module "@mariozechner/agent"`（agent/src/types.ts:309），与 coding-agent 实际使用的 `@earendil-works/pi-agent-core` 不一致——仅注释示例陈旧，机制无差别。
