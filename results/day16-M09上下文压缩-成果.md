## 一、章节核心要点（问题→机制）

- **问题**：对话无限增长会超模型上下文窗口，API 报 "prompt is too long"；直接删旧消息会让 Agent 失忆。**机制**：Compaction——把旧消息压成一段结构化摘要，用摘要替换原始消息。
- **时序**：压缩不在对话进行中触发，而在两轮之间——本轮结束检查 `shouldCompact()`，超阈值则找切割点→生成摘要→写 CompactionEntry 进 Session Tree；下一轮 `buildSessionContext()` 重建上下文，LLM 看到"摘要+近期消息"。
- **触发条件**：`contextTokens > contextWindow - reserveTokens`（默认 window 200K、reserve 16K，即红线 183,616）；reserveTokens 为 LLM 回复预留空间。分预防式（threshold）与应急式（overflow 报错后重试）两级。
- **Token 估算**：不用 tokenizer，`estimateTokens` 按角色累加字符后 `Math.ceil(chars/4)`——保守策略（宁可高估多压一次，不可低估触发 API 报错）；代价是中文被严重低估（1 汉字约 1-2 token 只算 0.25）。
- **切割点**：`findValidCutPoints` 只允许 user/assistant 等开启 Turn 的消息，**toolResult 必为非法切点**（toolResult 必须紧跟其 toolCall）；切点语义是"保留区第一条"。
- **向后遍历**：`findCutPoint` 从最新往回累积 token 至 `keepRecentTokens`（20K），选最近的有效切点——最近的上下文最重要。
- **结构化摘要**：`SUMMARIZATION_PROMPT` 强制填 6 section（Goal / Constraints & Preferences / Progress 含 Done/In Progress/Blocked / Key Decisions / Next Steps / Critical Context），对抗 LLM 自由发挥遗漏核心需求；`UPDATE_SUMMARIZATION_PROMPT` 支持把 previousSummary 合并做增量更新而非重写。
- **Turn 分割补偿**：允许 assistant 切点（仅 user 切点会压不动），切断的半个 Turn 由 `TURN_PREFIX_SUMMARIZATION_PROMPT`（3 段：Original Request / Early Progress / Context for Suffix）单独生成 turnPrefix 摘要，与主摘要合并同存一个 CompactionEntry。
- **领域知识**：`extractFileOperations` 把上次压缩 details 的文件列表与本次工具调用文件合并，用 `<read-files>`/`<modified-files>` 标签附在摘要末尾，跨压缩累积。

## 三、验证的关键结论

1. **触发公式逐字符一致**：compaction.ts:236-237 `if (!settings.enabled) return false; return contextTokens > contextWindow - settings.reserveTokens;`；默认值 `DEFAULT_COMPACTION_SETTINGS`（132-135）enabled:true、reserveTokens:16384、keepRecentTokens:20000。
2. **chars/4 估算按 6 种角色分支**：compaction.ts:266-306，assistant 累加 text/thinking/toolCall(name+arguments)（281-285），bashExecution 累加 command+output（294-296），compactionSummary/branchSummary 用 summary（298-302）；注释 263-264 明言 "conservative (overestimates tokens)"。
3. **split-turn 判定**：compaction.ts:451-459 `startsTurn = isTurnStartEntry(cutEntry)`、`turnStartIndex = startsTurn ? -1 : findTurnStartIndex(...)`、`isSplitTurn: !startsTurn && turnStartIndex !== -1`；本地用"Turn 起点角色集"（isTurnStartMessage 323-336 含 bashExecution/custom/branchSummary/compactionSummary）代替单一 `role === "user"`。
4. **cutIndex 后 metadata 归并循环**（compaction.ts:442-449）：向前吞并无上下文可见的相邻元数据 entry，教程未提；"切点=保留区第一条"语义在 `firstKeptEntryIndex`（380）注释中直接写明。
5. **摘要合并格式**：compaction.ts:925 `summary = ${historyText}\n\n---\n\n**Turn Context (split turn):**\n\n${turnPrefixResult.text}`；LLM 侧注入文案 messages.ts:11 `The conversation history before this point was compacted into the following summary:\n\n<summary>`。

## 四、矛盾 / 漂移 / 疑问

- **并行→串行（唯一实质性矛盾）**：教程称主摘要与 turnPrefix 摘要用 `Promise.all` 并行生成（v0.83 L784-813）；本地 0.85.1 在 compact() 内是连续两个裸 await（compaction.ts:891、910），时间上串行，仅结果合并（925-926）。语义结果等价，但效率与教程描述不符。
- **触发挂载点漂移**：教程说自动压缩嵌在 `agent_end` 事件处理中；本地是两处——`prepareNextTurnWithContext` 拦截的 `_compactBeforeNextAssistantResponse`（agent-session.ts:538-555, 557-579）和运行后的 `_checkCompaction`（约 2204-2257，阈值触发在 2255）。"两轮之间"时序成立，但具体钩子从 agent_end 换到下一轮准备阶段。
- **小新增**：`ESTIMATED_IMAGE_CHARS = 4800`（compaction.ts:244）图片字符估算、`CompactionResult.estimatedTokensAfter`（93）、`completeSummarization` 统一重试入口（579+）均为教程未覆盖。
- **疑问（未深究）**：overflow 分支（2191-2223）中 `_runAutoCompaction("overflow")` 会 `agent.continue()` 重试被中断的回合——教程只一句"先压缩再重试"，willRetry 语义在 `_runAutoCompaction` 返回值注释（2268）才说清。

## 五、一句话总结

教程对压缩算法核心（阈值公式、chars/4 估算、toolResult 禁切、6-section 摘要、turnPrefix 补偿、CompactionEntry 重建上下文）与本地 0.85.1 逐行吻合，仅两处漂移：主/前缀摘要由并行改串行、自动触发挂载点由 agent_end 移入 prepareNextTurn 拦截。
